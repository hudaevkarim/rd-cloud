# rd-cloud

Централизованное веб-приложение для совместного чтения книг и прослушивания
аудиокниг. Сервер — единственный источник правды.

Наследник P2P-проекта [`rd`](https://github.com/hudaevkarim/rd): тот же функционал,
но с сервером. Это даёт работу на iOS и Android, нормальную работу в фоне и
синхронизацию между устройствами.

---

## Требования к машине разработчика

| Что | Версия | Где лежит |
|---|---|---|
| Node.js | 22 LTS (22.23.3) | `tools/node` — portable, в репозитории |
| PostgreSQL | 16.14 | `C:\rcdb\pgsql` и `C:\rcdb\pgdata` |
| Git | 2.56 | `C:\Program Files\Git\cmd` (системный) |

Ничего из этого не обязано стоять в `PATH`: скрипт `tools/env.ps1` собирает
окружение сам. Docker не используется и не нужен.

---

## Первый запуск

```powershell
# 1. Разрешить скрипты PowerShell (один раз, права админа не нужны)
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

# 2. Поднять PostgreSQL
.\tools\pg-start.ps1

# 3. Подключить окружение (node, npm, git, переменные из .env)
. .\tools\env.ps1

# 4. Поставить зависимости
npm install

# 5. Применить миграции и создать первого администратора
npm run db:migrate
npm run db:seed
```

Проверка:

```powershell
node -v      # v22.23.3
git --version
.\tools\pg-stop.ps1
```

## Устройство окружения

Три вещи в этом проекте живут не там, где ожидаешь. Каждая — по причинам,
проверенным экспериментом, а не по умолчанию.

### 1. PostgreSQL лежит в `C:\rcdb`, а не в репозитории

PostgreSQL на Windows открывает файлы через ANSI-кодовую страницу системы, а
здесь она `cp1251`. Путь с кириллицей (`C:\Users\роман\...`) он прочитать не
может и падает:

```
FATAL:  invalid byte sequence for encoding "UTF8": 0xf0 0xee 0xec 0xe0
```

`0xf0 0xee 0xec 0xe0` — это «роман» в cp1251.

Node, npm, tsc, esbuild и Prisma с кириллическими путями работают нормально —
проверено. Негодный только сам Postgres. Поэтому `data/pg` лежит отдельно, а
данные приложения (`DATA_DIR=./data`) остаются в репозитории: их читает Node.

### 2. Node portable внутри репозитория

В системе Node установлен (v24.21.0), но в `PATH` не прописаны и `node`, ни
`git`. Чтобы проект зависел от состояния системы, Node 22 LTS положен в
`tools/node` (в git не попадает — см. `.gitignore`), а `env.ps1` добавляет его в
`PATH` вместе с системным Git.

### 3. Файлы `.ps1` сохраняются в UTF-8 с BOM

Windows PowerShell 5.1 читает `.ps1` без BOM в ANSI-кодовой странице. Русские
комментарии в таком файле превращаются в мусор и ломают разбор скрипта. Все
скрипты в `tools/` записаны с BOM; при редактировании это нужно сохранять.

### Следствие для всего проекта

**Кириллицу нельзя передавать в аргументах командной строки нативным программам.**
PowerShell отдаёт их в cp1251, программа ждёт UTF-8 — и падает. Тот же psql
отвечает `ERROR: invalid byte sequence for encoding "UTF8"` на запрос, в котором
кириллица стоит аргументом `-c`.

Отсюда правило: SQL и текст передавать файлами (`psql -f`, `prisma migrate
edit` с файлом), а не аргументами. Внутри приложения проблемы нет — оно
занимается UTF-8 через Node и драйвер `pg`.

## Схема доступа к комнатам

Приватных комнат нет: админ видит всё содержимое. Различаются только способы
входа.

| Способ | Что происходит |
|---|---|
| `inviteCode` из ссылки-приглашения | вход сразу, без одобрения |
| Поиск публичных комнат (`isPublic: true`) | создаётся `JoinRequest`, участник одобряет |
| Прямая ссылка на `isPublic: false` | только по приглашению |

## Каталог и файлы

```
data/
  files/<bookId>/original.<ext>        исходный файл
  derived/<bookId>/index.json          главы, оглавление, число блоков
  derived/<bookId>/ch/<n>.json         блоки одной главы
  covers/<bookId>.<ext>                обложка
```

Книга разбирается на сервере один раз при загрузке. Клиент читает `index.json`
(десятки килобайт) и подгружает главы по мере надобности — вместо того чтобы
скачивать мегабайтный EPUB целиком, как это было в `rd`.
