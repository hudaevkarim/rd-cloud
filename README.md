# rd-cloud

Централизованное веб-приложение для совместного чтения книг и прослушивания
аудиокниг. Сервер — единственный источник правды.

Наследник P2P-проекта [`rd`](https://github.com/hudaevkarim/rd): тот же
функционал, но с сервером. Ради этого всё и затевалось — в `rd` на мобильном
не работало фоновое прослушивание из-за ограничений WebRTC.

## Состояние

```
packages/
  library/   разбор EPUB/FB2, якоря, рендеринг   ← готов, 83 теста
  shared/    якоря комментариев, роли, DTO       ← validateAnchor
  server/    Fastify + Prisma + статика           ← комнаты, книги, админка
  web/       React + Vite + Tailwind             ← пусто
```

**Есть:** схема БД (11 таблиц) и миграция, аутентификация по токену, админка,
комнаты с приглашениями и заявками, загрузка книг с разбором на сервере,
каталог, комментарии с курсорной пагинацией и реакциями, Socket.IO с
присутствием и уведомлениями. 155 тестов плюс проверка сокетов двумя
клиентами.

**Нет:** клиента, чтения уведомлений через REST.

## Аутентификация

Токен выдаёт админ: 32 случайных байта в base64url. **В базе лежит только
sha256** — дамп не даёт доступ к аккаунтам. Ни JWT, ни паролей: сессия это сам
токен, сравнение идёт по хешу. `SESSION_SECRET` в `.env` нет — подписывать
нечего.

Токен принимается тремя способами, и это не избыточность:

| Способ | Где | Зачем |
|---|---|---|
| `Authorization: Bearer` | `/api` | основной; не попадает в историю и `Referer` |
| cookie `rd_token` | `/files/**` | браузер не умеет вешать заголовок на `<img>` и `<audio>` |
| `?t=<token>` | только `/files/**` | запасной путь для `<img>`/`<audio>` |

`?t=` на `/api` запрещён: токен в URL попадает в логи, историю и `Referer`.

Cookie: `HttpOnly`, `SameSite=Lax`, `Secure` в production, срок год. **Оговорка
про разработку:** `Lax` не переносит cookie в XHR и в `<img>` с *другого*
origin, а в разработке клиент на `:5173`, а API на `:3000`. Либо ходить через
прокси Vite (тогда всё один origin), либо в разработке передавать токен
заголовком и в `?t=`. В production оба домена за одним Cloudflare Tunnel, и
cookie работает сама.

## Что закрыто

**Rate-limit на входе** — 10 в минуту на адрес, ключ — IP, а не токен: иначе
перебор разными токенами обходил бы его. Живёт в одном encapsulated-контексте
с маршрутами входа, иначе не срабатывает вовсе.

**Path traversal** — три ступени: отбрасываются `\` и `%2F`, затем
декодируется percent-encoding и ищутся `..`, и итоговый путь обязан лежать
внутри `DATA_DIR`. Последняя ступень не может ошибиться. Проверено
`curl --path-as-is` на `../`, `%2e%2e%2f`, `..%5c`, `....//`.

**Диапазон аудио** — `Range: bytes=0-99` даёт `206` и ровно 100 байт.

**CORS** — ровно один origin из `WEB_ORIGIN`; чужому origin заголовок не
выдаётся.

## Загрузка файлов

`multipart/form-data`. **Текстовые поля обязаны идти раньше файла** — иначе
сервер не знает, какой лимит применять (50 МБ для текста, 2 ГБ для аудио),
и откажет.

Поля: `kind` (`text`|`audio`), `format`, `title`, `author`, опционально
`description`, `language`, `year`, файл в поле `file`.

Порядок на диске и в базе выбран так, чтобы не оставалось «книги без файла»:
файл пишется в `original.part`, после успешного конца переименовывается, и
только потом появляется запись в базе. Обрыв соединения удаляет и файл, и его
каталог.

## `@rd/library`

Перенесена из `rd` без изменения логики, разрезана на три точки входа — и это
не косметика, а условие того, что сервер вообще может её импортировать:

| Точка входа | Где работает | Что внутри |
|---|---|---|
| `@rd/library/parse` | Node и браузер | `xml`, `encoding`, `epub`, `fb2`, видимость глав |
| `@rd/library/anchor` | Node и браузер | якоря комментариев, `BookIndex`, спойлеры |
| `@rd/library/render` | только браузер | вывод книги в DOM без `innerHTML` |

При общей точке входа серверный импорт тянул бы модуль, работающий с `document`,
и падал бы на «рендерер доступен только в браузере». По той же причине чистые
функции видимости вынесены из `render` в `parse`.

Не перенесены `room-doc.ts` (Yjs — состояние в Postgres) и `storage.ts`
(Dexie — файлы на диске сервера).

## Как книга попадает к читателю

```
загрузка (один раз)   сервер разбирает EPUB/FB2 сам и пишет
                      data/derived/<fileId>/index.json
                      data/derived/<fileId>/ch/0000.json

чтение                клиент берёт index.json (десятки КБ) и подгружает
                      главы по мере надобности
```

В `rd` клиент скачивал книгу целиком и разбирал у себя. На телефоне это и было
главным препятствием.

Идентификатор каталога на диске — UUID, выданный при загрузке, а не `BookFile.id`
из базы. Поэтому производные пути берутся из колонки `derivedPath`, а не
собираются из идентификатора записи: это разные значения, и подстановка одного
вместо другого молча указывала бы на несуществующий каталог.

## Сокеты

Socket.IO работает на том же HTTP-сервере, что и Fastify, отдельного порта
не занимает: `engine.io` отдаёт запросы не-сокетов прежним слушателям.

Токен передаётся в `socket.handshake.auth.token` **или** в cookie `rd_token`.
Без токена рукопожатие отклоняется с `unauthorized`.

События клиента: `room:join`, `room:leave`, `presence:update`.
События сервера: `room:left`, `presence:changed`, `presence:left`,
`comment:new`, `comment:updated`, `comment:deleted`, `reaction:changed`,
`notification:new`, `server:ready`.

Сокет — **сигнал, а не источник правды**. В payload лежит полный объект, чтобы
клиент вставил его без дополнительного запроса, но authoritative-версия всегда
в REST: потерянное событие приводит к «недостающему» комментарию до следующей
перезагрузки ленты, а не к рассинхрону с сервером.

Вещание исключает **автора изменения**, а не отправителя события. Комментарий
создаётся через REST, где сокета нет, а `except()` в Socket.IO принимает имя
комнаты — исключается персональный канал `user:<id>`, и вместе с ним отпадают
все вкладки автора.

Присутствие держится в памяти и обновляется мгновенно, в базу сбрасывается раз
в 15 секунд. Записывать его на каждое перелистывание абзаца нельзя: это темп
чтения, а не темп изменений.

Проверка: `npm run test:socket`. Скрипт поднимает сервер на порту 3399,
подключает двух клиентов и одного постороннего, проверяет отказ без токена,
вход в комнату, вещание комментария, присутствие, обрыв и уведомления. Он
сам переключает базу на `rdcloud_test` и отказывается работать иначе, чтобы не
писать в рабочую.

### Ловушка: смещение в `$queryRaw`

Prisma 7 через `@prisma/adapter-pg` связывает параметры типа `Date` как стенное
время без смещения. На машине с `TimeZone = Europe/Saratov` значение
`2026-01-01T00:00:00.245Z` записывается как `2026-01-01 00:00:00.245+04` — на
четыре часа раньше. Обратно Prisma читает его так же, поэтому у себя всё
согласовано, а Postgres, разбирая строковый литерал `'...Z'::timestamptz` по
ISO 8601, понимает его правильно и получает `04:00:00.245+04`.

Сравнение сохранённого значения с таким литералом отсекает всё: вторая страница
курсорной пагинации приходит пустой. Поэтому в сыром SQL границы передаются
объектами `Date` — так же, как Prisma связывает их при записи.
