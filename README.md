# rd-cloud

Централизованное веб-приложение для совместного чтения книг и прослушивания
аудиокниг. Сервер — единственный источник правды.

Наследник P2P-проекта [`rd`](https://github.com/hudaevkarim/rd): тот же
функционал, но с сервером. Ради этого всё и затевалось — в `rd` на мобильном
не работало фоновое прослушивание из-за ограничений WebRTC.

## Состояние

```
packages/
  library/   разбор EPUB/FB2, якоря, рендеринг   ← готов, 83 теста
  shared/    общие типы и схемы валидации         ← пусто
  server/    Fastify + Prisma + статика           ← аутентификация, админка
  web/       React + Vite + Tailwind             ← пусто
```

**Есть:** схема БД (11 таблиц) и миграция, сид администратора, `/health`,
раздача файлов, вход по токену, админ-панель. 120 тестов.

**Нет:** комнат, книг, комментариев, Socket.IO, клиента.

## Запуск

```powershell
.\tools\pg-start.ps1     # PostgreSQL
. .\tools\env.ps1         # node, npm, git, переменные из .env
npm install
npm run db:migrate       # применить миграции
npm run db:seed          # создать первого администратора, напечатает токен
npm run dev              # сервер на http://127.0.0.1:3000
```

Проверка:

```powershell
curl http://127.0.0.1:3000/health
# {"status":"ok"}
```

Один раз вручную: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`

**Подробности про окружение — в [`docs/environment.md`](docs/environment.md).**
Там четыре находки, каждая из которых ломала работу по отдельности: кириллица в
пути, за тегом `latest` у Prisma лежит release candidate, `.ps1` без BOM ломает
разбор скрипта, `global: false` у `@fastify/rate-limit` не означает «только этот
префикс».

Серверные тесты ходят в **отдельную** базу `rdcloud_test` и делают `TRUNCATE`.
`setup-файл` откажется работать, если в `TEST_DATABASE_URL` нет подстроки
`rdcloud_test`: перепутать базу и снести рабочие данные невозможно.

```powershell

```

В CI Postgres поднимается сервис-контейнером, локально — из `C:\rcdb`.

## Аутентификация

Токен выдаёт админ: 32 случайных байта в base64url. **В базе лежит только
sha256** — дамп не даёт доступ к аккаунтам. Ни JWT, ни паролей: сессия это сам
токен, сравнение идёт по хешу. `SESSION_SECRET` в `.env` нет — подписывать
нечего.

Токен принимается тремя способами, и это не избыточность:

| Способ | Где | Зачем |
|---|---|---|
| `Authorization: Bearer` | `/api` | основной; не попадает в историю и `Referer` |
| cookie `rd_token` | `/files/**` | браузер не умеет вешать заголовок на `<img>` и `<audio>` |
| `?t=<token>` | только `/files/**` | запасной путь для `<img>`/`<audio>` |

`?t=` на `/api` запрещён: токен в URL попадает в логи, историю и `Referer`.

Cookie: `HttpOnly`, `SameSite=Lax`, `Secure` в production, срок год. **Оговорка
про разработку:** `Lax` не переносит cookie в XHR и в `<img>` с *другого*
origin, а в разработке клиент на `:5173`, а API на `:3000`. Либо ходить через
прокси Vite (тогда всё один origin), либо в разработке передавать токен
заголовком и в `?t=`. В production оба домена за одним Cloudflare Tunnel, и
cookie работает сама.

## Что закрыто

**Rate-limit на входе** — 10 в минуту на адрес, ключ — IP, а не токен: иначе
перебор разными токенами обходил бы его. Живёт в одном encapsulated-контексте
с маршрутами входа, иначе не срабатывает вовсе.

**Path traversal** — три ступени: отбрасываются `\` и `%2F`, затем
декодируется percent-encoding и ищутся `..`, и итоговый путь обязан лежать
внутри `DATA_DIR`. Последняя ступень не может ошибиться. Проверено
`curl --path-as-is` на `../`, `%2e%2e%2f`, `..%5c`, `....//`.

**Диапазон аудио** — `Range: bytes=0-99` даёт `206` и ровно 100 байт.

**CORS** — ровно один origin из `WEB_ORIGIN`; чужому origin заголовок не
выдаётся.

## API

| Метод | Путь | Кто |
|---|---|---|
| `GET` | `/health` | все |
| `POST` | `/api/auth/login` | все, 10/мин с IP |
| `GET` | `/api/auth/me` | вход |
| `POST` | `/api/auth/logout` | все |
| `GET` | `/api/admin/users` | админ |
| `POST` | `/api/admin/users` | админ |
| `DELETE` | `/api/admin/users/:id` | админ, не себя |
| `GET` | `/api/admin/rooms` | админ |
| `DELETE` | `/api/admin/rooms/:id` | админ |
| `GET` | `/api/admin/stats` | админ |
| `GET` | `/files/**` | токен в cookie или `?t=` |

## `@rd/library`

Перенесена из `rd` без изменения логики, разрезана на три точки входа — и это
не косметика, а условие того, что сервер вообще может её импортировать:

| Точка входа | Где работает | Что внутри |
|---|---|---|
| `@rd/library/parse` | Node и браузер | `xml`, `encoding`, `epub`, `fb2`, видимость глав |
| `@rd/library/anchor` | Node и браузер | якоря комментариев, `BookIndex`, спойлеры |
| `@rd/library/render` | только браузер | вывод книги в DOM без `innerHTML` |

При общей точке входа серверный импорт тянул бы модуль, работающий с `document`,
и падал бы на «рендерер доступен только в браузере». По той же причине чистые
функции видимости вынесены из `render` в `parse`.

Не перенесены `room-doc.ts` (Yjs — состояние в Postgres) и `storage.ts`
(Dexie — файлы на диске сервера).

## Как книга попадает к читателю

```
загрузка (один раз)   сервер разбирает EPUB/FB2 сам и пишет
                      data/derived/<bookId>/index.json
                      data/derived/<bookId>/ch/<n>.json

чтение                клиент берёт index.json (десятки КБ) и подгружает
                      главы по мере надобности
```

В `rd` клиент скачивал книгу целиком и разбирал у себя. На телефоне это и было
главным препятствием.
