# rd-cloud

Централизованное веб-приложение для совместного чтения книг и прослушивания
аудиокниг. Сервер — единственный источник правды.

Наследник P2P-проекта [`rd`](https://github.com/hudaevkarim/rd): тот же
функционал, но с сервером. Ради этого всё и затевалось — в `rd` на мобильном
не работало фоновое прослушивание из-за ограничений WebRTC.

## Состояние

Скелет монорепозитория и библиотека разбора книг. Сервер, база и клиент ещё не
написаны.

```
packages/
  library/   разбор EPUB/FB2, якоря комментариев, рендеринг  ← готов, 83 теста
  shared/    общие типы и схемы валидации                   ← пусто
  server/    Fastify + Prisma + Socket.IO                    ← пусто
  web/       React + Vite + Tailwind                        ← пусто
```

## Требования к машине

| Что | Версия | Где |
|---|---|---|
| Node.js | 22 LTS | `tools/node` — portable, в репозитории |
| PostgreSQL | 16.14 | `C:\rcdb` |
| Git | 2.56 | системная установка |

Ничего из этого не обязано быть в `PATH`. Docker не нужен.

## Запуск

```powershell
.\tools\pg-start.ps1     # PostgreSQL
. .\tools\env.ps1         # node, npm, git, переменные из .env
npm install
npm run typecheck
npm test
```

Один раз вручную: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`

**Подробности про окружение — в [`docs/environment.md`](docs/environment.md).**
Там три находки, каждая из которых ломала работу по отдельности: кириллица в
пути, за тегом `latest` у Prisma лежит release candidate, `.ps1` без BOM ломает
разбор скрипта.

## `@rd/library`

Перенесена из `rd` без изменения логики. Разрезана на три точки входа — и это не
косметика, а условие того, что сервер вообще может её импортировать:

| Точка входа | Где работает | Что внутри |
|---|---|---|
| `@rd/library/parse` | Node и браузер | `xml`, `encoding`, `epub`, `fb2`, видимость глав |
| `@rd/library/anchor` | Node и браузер | якоря комментариев, `BookIndex`, спойлеры |
| `@rd/library/render` | только браузер | вывод книги в DOM без `innerHTML` |

Если бы всё лежало в одной точке входа, серверный импорт тянул бы модуль,
работающий с `document`, и падал бы на «рендерер доступен только в браузере».
По этой же причине чистые функции видимости вынесены из `render` в `parse`:
серверу они нужны, чтобы не отдавать оглавление с пустыми главами.

Не перенесены `room-doc.ts` (Yjs — в централизованной версии состояние в
Postgres) и `storage.ts` (Dexie — файлы лежат на диске сервера).

## Как книга попадает к читателю

```
загрузка (один раз)     сервер разбирает EPUB/FB2 сам и пишет
                       data/derived/<bookId>/index.json
                       data/derived/<bookId>/ch/<n>.json

чтение                 клиент берёт index.json (десятки КБ) и подгружает
                       главы по мере надобности
```

В `rd` клиент скачивал книгу целиком и разбирал её у себя. На телефоне это и
было главным препятствием.
