# Чек-лист ревью

Проверки, которые выведены из повторяющихся поломок. Каждая причина была
найдена в живом браузере и не ловилась тестами: тесты проверяли намерение, а
браузер показывал результат.

---

## 1. StrictMode

`main.tsx` оборачивает приложение в `<StrictMode>`. В разработке он включён, а в
тестах — нет, если обёртка не поставила его руками. Это и есть источник класса
поломок ниже.

**Что происходит.** React вызывает тело компонента дважды и смонтированные
эффекты — тоже дважды. Отбрасывается первая попытка.

### 1.1. `setState` во время рендера

```tsx
// НЕЛЬЗЯ
if (ready && !done.current) {
  done.current = true;
  setValue(saved);          // отбрасывается вместе с первой попыткой
}
```

Флаг в ссылке успевает встать, обновление — нет. Итог: восстановление позиции
читалось, номер главы менялся и тут же терялся; книга открывалась с начала.
Наблюдалось в 7.4.1: в хранилище `chapter: 8`, в журнале сервера запроса
`ch/8.json` нет.

**Как правильно.** Действие, меняющее состояние, — в эффекте, а не в теле
компонента.

### 1.2. Одноразовые задачи, которые съедаются первым проходом

```tsx
const pending = useRef<T | null>(null);
// эффект вызовется дважды
onRendered() {
  const task = pending.current;
  pending.current = null;      // второй вызов уже не увидит задачу
  restore(task);
}
```

Второй проход видел пустую задачу и уводил прокрутку в начало сразу после того,
как первый её вернул. Наблюдалось в 7.4.1: `scrollY: 8000` сохранён, а глава
открывалась наверху.

**Как правильно.** Либо задача живёт до явной отмены, либо восстановление
идемпотентно — повторный вызов даёт тот же результат.

### 1.3. Проверки без StrictMode

Любая проверка страницы с состоянием должна рендерить внутри `<StrictMode>`,
иначе она проверяет поведение, которого в разработке нет. В 7.2 так ломался
вход по коду, в 7.4.1 — восстановление позиции.

## 2. Координаты и раскладка

### 2.1. `offsetTop` и `scrollTop` — разные системы координат

`offsetTop` элемента отсчитывается от ближайшего **позиционированного**
предка. `scrollTop` — от прокручиваемого контейнера. Если контейнер не
позиционирован, предком оказывается `body`, и две эти величины сравниваются
как координаты из разных систем.

Наблюдалось в 7.4.1: `scrollTop: 8000`, блок найден, а страница открылась
наверху.

**Как правильно.** Прокручиваемый блок — `position: relative`. Тогда
`offsetTop` абзацев отсчитывается от него же, и обе величины живут в одном
пространстве.

### 2.2. Раскладка после вставки — вручную

Присваивание `scrollTop` сразу после `appendChild` обрезается нулём: браузер
ещё не измерил высоту только что вставленного текста. Нужно прочитать
`scrollHeight` — это заставляет досчитать раскладку.

### 2.3. Ссылки заполняются при фиксации, эффекты идут после

Контейнер, созданный в том же проходе рендера, что и пришедшие данные, ещё
не попал в `ref` на момент выполнения эффекта, который его ищет. Ссылка в
замыкании — `null`.

Наблюдалось в 7.4.1: восстановление позиции не срабатывало никогда.

**Как правильно.** Передать элемент из того компонента, который его создал, а не
искать через свою ссылку.

## 3. Свойства, которые не работают без видимости

### 3.1. `requestAnimationFrame` и CSS-переходы в фоновой вкладке

Кадры не рисуются, и `rAF` не вызывается вовсе. Переходы и анимации встают на
паузе. Таймеры — работают, с ограничением частоты.

Наблюдалось в 7.4.1 дважды: позиция перестала записываться, пока человек
смотрел соседнюю вкладку; и `transform` панели застревал на начальном
значении при проверке в фоне.

**Как правильно.** Всё, что пишет в хранилище или меняет состояние по ходу
чтения, огрублять таймером, а не `rAF`. В коде — обязательно объяснение
причины: `rAF` выглядит «правильнее», и без комментария его вернут обратно.

### 3.2. Что видит проверка, а что — человек

Фоновая вкладка в инструменте — источник ложных выводов в обе стороны:
анимация «не сработала» и «сработала не там». Проверять стили без перехода,
либо называть это ограничением честно.

## 4. Данные на границе с сервером

Поле, на которое опираются потомки, проверяется на границе. Значение
недопустимого вида бросает ошибку, а не превращается в «почти правильное».

Наблюдалось в 7.4.1: блок без номера получал `data-block="undefined"`, якорь
превращался в `NaN`, и комментарий молча привязывался к несуществующему месту.
Сейчас это падение на границе — см. `applyBlockMeta` в `@rd/library/render` и
`tests/render/data-block-contract.test.tsx`.

**Вопрос к себе:** что ещё приходит с диска или с сервера и уходит дальше без
проверки? Тип в TypeScript проверяет компиляцию, а не содержимое файла.

## 5. Мобильный экран

Окно инструмента держится на десктопной ширине, и `@media` не применить.

**Работающий приём:** узкий `iframe` внутри страницы даёт своему документу
настоящий узкий вьюпорт — и `@media`, и `matchMedia` внутри него видят 320px.
Проверено в 7.4.1 для читалки: ширина 318px, выдвижное оглавление, шрифт
18px, кнопки перехода на всю строку.

**Что при этом не работает:** переходы и анимации в фоне (п. 3.1). Проверять
стиль, отключив переход, и говорить об этом в отчёте.

## 6. Проверки, которые проходят вхолостую

**jsdom не раскладывает страницу.** `offsetTop`, `scrollHeight`, размеры — все
нули. Проверка «значение равно смещению блока» проходит при любом коде.

**Подменять надо явно и до рендера:** задавать прототипные свойства, а не
элементы после отрисовки — страница меряет в тот же кадр, когда блоки
появились.

**Правило:** перед тем как закрыть проверкой «оно зелёное», убрать
защищаемое правило и убедиться, что проверка падает. Если зелёная — она ни
о чём не говорит.
